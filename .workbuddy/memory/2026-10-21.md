# 2026-10-21

## freellmapi 对照分析（回答用户三问）

- 结论：Freeport 与 freellmapi **核心骨架同源**（单点聚合 / 四窗口账本 / 冷却阶梯 / 签名目录 / 压缩 / 缓存 / 粘性 / fallback trail），但实现路线不同：Rust 单机桌面 vs Node 多用户服务端；账本按**凭据**而非 (platform,model,key)。
- 代码核对的事实：
  - 无 in-flight lease 对象、无 lease 年龄上限、无 per-key 并发上限；`Ledger::reserve/settle` 是它的等价物但失败不回滚。
  - 冷却只有 `hits` + reason 字符串，**没有** heuristic/authoritative/credit/tier 四档来源；探针只更新健康度，不解冷却。
  - 无 per-model 窗口维度（`Ledger::key` 只有 `provider:kind`，provider 实为 account id）。
  - 无 decision 路由 / fusion / per-model weight override / peak-hours / 统一模型组（只有 alias）。
- Pro 现状：脚手架齐（JWT `feat`、`x-freeport-tier`、仅 Pro 带 Bearer、manifest.tier 进签名、`feed_tier_e2e`），但 `feat` **无任何消费者**、无目录服务端 → 目前只是「声明了档位，还没发不同数据」。
- Pro 设计定调：只控「服务端给什么数据」（节奏 / 字段深度 / 补丁链 / 云端同步与日志保留 / 席位），不控转发链路、路由、注入、MCP、协议面。

## 第三轮：`/v1/completions`（旧版补全协议）

- 新增 `crates/freeport-gateway/src/completions.rs`：`to_chat` / `from_chat` / `sse_transform`。
  入口 `server.rs::completions_entry`，路由 `POST /v1/completions`，与 messages / responses 同构
  （转成 chat 走同一条接力链，响应再改回旧形状）。
- 边界（**拒绝而不是猜**）：`prompt` 只接受单条字符串（多条=批量补全，chat 没这个语义）、
  不接受 token id 数组、不接受 `suffix`（要上游原生 FIM）→ 三种都 400 `unsupported_parameter`。
  `echo` 在本地实现（拼回 text 前面，不透上游）；`tool_calls` 收尾降级 `stop`；
  `best_of`/`logprobs`/`top_logprobs` 不透传（多一个键就是一次 400 换家）。
- 踩到的坑：流式块原本每块各造一个 id（`legacy_id("")` 每次生成新 UUID），客户端会把一段补全
  看成好几段 → 改成整条流共用 `St.id`。单测 `chunks_without_upstream_id_share_one_generated_id` 锁住。
- 验证：`cargo test -p freeport-gateway` 122 lib + 31 个 e2e 全 ok（新增 6 条单测 + `completions_e2e`）。
- 文档：ARCHITECTURE §3.7 加一行入口 + 实现状态 + 边界说明（「四个协议入口」改「五个」）；
  GAP-ANALYSIS 补齐表加一行、进度表 #2 与「仍缺」列表同步（embeddings 现在唯一理由：目录里没有 embedding 模型）。

## 第四轮：统一模型组

- 语义定调（动了既有契约）：裸模型名 = **组**——声明这个 id 的每一家（含各自全部凭据）都入链，
  不再「取第一个声明它的那家」（那等于把「5 家都能跑」缩成 1 条通道）。
  落点 `route.rs::group_of`，调用在 `plan_with` ① 裸名分支。
- **显式点名不再补别的模型兜底**：`provider:model` 与裸名都只在该（组）内接力；
  L2/L3 链与 ③ 兜底只对 `auto` 生效。点名无路可走回 503，消息说清原因
  （未接入/已下架/凭据不可用/额度耗尽），`payload.requested` 带上点名。
  两个旧测试改了断言以反映新契约：`tombstoned_model_is_gated_out`（点名下架 → 空 + auto 照常）、
  `vision_request_skips_model_declared_text_only`（点名不满足能力 → 拒绝 + auto 绕行）。
- 对外可见性：别名 ≥2 家收敛成 `claude-freeport-<model>`（组，`AliasEntry.members`），
  单家仍 `claude-freeport-<provider>:<model>`；`alias_json` 三分支（virtual / group / 单家）；
  `aggregate_models` 每行带 `freeport.alsoOn`（camelCase，去掉自己后非空才出现），
  模型页显示「N 家」徽标。`is_auto` 改 pub（server 判点名用）。
- 验证：core 127 passed（+5）；`cargo test -p freeport-gateway` 122 lib + 全部 e2e ok；
  `cargo check --workspace` 干净；`tsc --noEmit` 通过。
- 仍缺：per-model 窗口第二维、`/v1/embeddings`、`feat` 字段级下发。

## 第七轮：`feat` 字段级下发（Pro 最后一项）

- 形态定调：**字段包是旁路文档，不切快照**。快照字节被 sha256 + 补丁链钉死，
  再切一刀就要重序列化（有浮点价格，JCS 直接拒）、多一条补丁链、多一次「给谁哪份」判断。
- `freeport-catalog`：`FeatRef{name,url,sha256}`；`Manifest.feat`（非空才进签名载荷）；
  `Applied.feats/feats_skipped`；`apply_feat(cat,name,value)` 只认 `FEAT_QUOTA_INTEL`，
  只补既有厂商、只覆盖包里明说的字段；`poll()` 末尾 `apply_feats()` 逐份拉，
  **任何一份失败只记原因不推翻快照**。`KNOWN_FEATS` 先于下载：先信后懂等于把解析器交给发布方。
- `freeport-catalogd`：`Floor.feats`（`feats/<name>.json`，名字字符集白名单）、
  `feats_for(&[String])` 按令牌 feat 名单挑（大小写不敏感）；HTTP 壳搬到 `src/http.rs`
  以便 e2e 直接挂真实路由；`/v1/feat/:name` 与 `/v1/snapshot/live.json` 都验令牌
  （地址可猜，不守等于所有人直取实时档）。**修掉一个真 bug**：manifest 里的相对地址
  按 `.../v1/latest` 解析会落在 `/v1/snapshot/...`，而路由只注册了根路径 → 快照 404；
  现在两组路径都注册。
- 发布侧 `examples/sign_feed.rs --feats <dir>`：复制到 `feed/feat/` + 摘要进 manifest。
- 客户端状态：`FeedState.served_feats/feats_skipped`（camelCase 显式 rename）→ `GwFeed` 同名 →
  设置页「本次下发」一行（pro/公共目录徽标 + 跳过原因）。
- 刻意不做：不把 `quota.intel` 自动写进账本限额——过期的情报拦住本来能成的请求，
  违背「宁可只记账不误拦」。情报只在发现页展示（`p.quota` 早就渲染）。
- 验证：catalog 31 passed、catalogd 7 passed、`feat_e2e` 真实 catalogd 对打真实网关 ok、
  gateway 全量回归见任务 hbePJj；`tsc --noEmit` 通过。

- 核心判断：
  1. **成功判定点错位**是最大缺口 —— `server.rs:1117` 在 `stream` 分支前就 `note_success`/`ok=true`，而免费额度主要失败在 200 之后（空流/错误体/中途断）。账本因此写假阳性。
  2. 流式是纯 passthrough（`server.rs:1235-1295`），中途断流只发 SSE error，无法 failover → 需引入 **Hold 缓冲门**（magpie 的 holdWriter）：首个有效语义块（text/reasoning/tool_call）才 commit，15s 未就绪发 SSE 注释保活。
  3. 错误分类需从「只看状态码」扩到「状态码 + body 文本正则 + 响应形态」，补 200 体分支（中文关键词：余额/欠费/额度/套餐/限额已用完）。
  4. 第三缺口：**缺 `freeport-inject` crate**（现只有 core/gateway/catalog/probe），注入没有代码边界。
  5. 「中心」语义缺**虚拟 key（per-agent 配额）**，magpie 的 `gateway key 限额` 即此层。
  6. 明确不抄 magpie 的 Claude 订阅桥接（红线）；不用「配置双写」兜网关故障，改用 daemon + KeepAlive 进程自愈。
  7. 目录覆盖必须按 provider 逐条，禁止广播默认值（magpie 曾全局设 272K 把 Claude 1M 卡住）。

## 21:05 迁移码（多机同步 v1）
- 换了条线做**配置迁移**：Pro 多机同步不必先有服务端，换机最痛的是「重新抄一遍十几个 key」。

- 加密：Argon2id(m=19MiB,t=2,p=1) → AES-256-GCM；信封自带 KDF 参数与 salt/nonce，**AAD 就是参数本身**（改 salt 或改参数都解不开）。解密前校验 m≤256MiB/t≤16/p≤8，防止手写信封骗内存。
- 搬：providers（去模型目录、去健康度）、accounts（限额/启停）、secrets、api_keys（只搬 key_hash，**原客户端迁移后继续可用**）、routing、patrol。不搬：台账、冷却、健康、目录、端口与 authToken、OAuth token。
- 两种语义：`merge` 只补缺失、绝不覆盖同名凭据的 key；`replace` 整体替换且**先删本机多余凭据的密文**（否则「以为覆盖了，旧 key 还在盘上」）。
- Argon2 是 CPU-bound，`export/open` 都 `spawn_blocking`，别卡网关 runtime。
- 命令 `gw_export_bundle(passphrase)` / `gw_import_bundle(blob, passphrase, mode)`；新组件 `src/components/Transfer.tsx` 挂进设置页（口令两次确认、迁移码复制、覆盖需勾选）；`app.css` 加 `.transfer-box/.transfer-split/.transfer-warn`。

## M7.3 web 会话凭据（Cookie 形态）落地

**范围**：架构里 C3 只做 OpenCode Zen 一家试点，本轮把它做成完整可用的第三类凭据。

**`freeport-auth/src/cookie.rs`（RFC 6265 子集，13 单测）**
- 三种粘贴格式都认：`Cookie:` 单行、多行 `Set-Cookie`、DevTools 导出的 JSON 数组。
- 判断全在边界上：`notevil.com` 不能命中 `evil.com`（必须「点 + 域」结尾）；`/foo` 不能命中 `/foobar`（前缀处必须是 `/`）；`secure` 只走 https；过期不发。
- 排序按 RFC 6265 5.4（path 长的先发）——不少服务端「同名取第一条」，顺序错了等于发旧值。
- **CR/LF 直接拒**，不做「清洗后照发」：清洗过的值只会 401，还把真问题藏起来。
- `absorb()` 从 `Set-Cookie` 学轮换（`Max-Age: 0` = 删除；`Domain` 不属于当前站点就丢弃）。
- `host_only` 语义按 RFC：响应显式给 `Domain` 才是域 cookie（前导点只是写法）。

**`secrets` 第三个槽位 `{account}#cookie`**：AAD 同步带后缀，三类密文（key/oauth/cookie）互不通用；`has_credential` 对**全部过期的 jar 返回 false**——会话不自动续，让它占着候选位只是把权重浪费在必然 401 的一跳上。

**`gateway/src/cred.rs`（新模块）**：`Credential::{Bearer, Cookie{account_id, jar}}`，统一「这次请求发什么头」。
- `Credential::load`：**会话优先于 key**（用户专门配 cookie 说明这次走浏览器那条路）。
- `auth_pair(url)` 按 URL 现算 cookie——提前拼一个串等于把根路径会话也发给子路径。
- Cookie 时**绝不带 Authorization**：带着 Bearer 访问只认会话的端点会 401，还让上游看到一把它不认识的 token。
- `absorb()` 学 Set-Cookie 后立刻落盘（有变化才写）。

**`probe` 签名改成 `AuthHeader<'a> = (&'a str, &'a str)`**：探针不关心是 Bearer 还是 Cookie，只认「哪个头、什么值」。签名从 `key: &str` 换掉后，以后加凭据形态不用再改探针。

**网关接线**：`credential()` 返回 `Credential`（oauth > cookie > key）；chat 接力路径改成 `let Some(mut cred)`，成功后把响应的 `set-cookie` 当场 absorb；401/403 且是 cookie 时，错误文案改成「web 会话已失效，请到凭据页重新粘贴会话」，不再说 key 无效。新增 `add_cookie_account`（导入即校验，失败回滚并删密文）与 `set_account_cookie`（换会话顺手清旧 health）。预置厂商加 `opencode`（tier C，`https://opencode.ai/zen/v1`）。`with_auth_meta` 给 cookie 凭据标 `auth="cookie"`。

**前端**：`GwAccount.auth === 'cookie'` 显示「Web 会话」徽章，`hasKey` 为假时变成可点的「会话已过期」；tier C 卡片头多「会话」按钮（`COOKIE_PROVIDERS` 白名单只放 opencode，符合「Cookie 只做一家试点」）；`CookieDialog` 支持粘贴 + 说明「不读系统浏览器 Cookie、不自动续期」。

## M6.5.1 目录 feed 增量补丁（RFC 6902 链）

**协议**
- `Manifest.patches: Vec<PatchRef{fromSeq,toSeq,url,sha256}>`，**空数组不进签名**（老 manifest 签名不受影响）；非空时整组进 `signing_payload`——否则中间人能把 url 换成自己的服务器、交一份「只删不加」的补丁。
- `PatchFile{fromSeq,toSeq,ops,sha256After}`，patch 文件本身的 sha256 钉在 manifest 里（manifest 已签名），所以补丁不用单独签名。
- 只支持 `add/remove/replace/test`。**不做 move/copy**：它们能从任意路径读值写到另一路径，等于给补丁「读整份文档」的能力，收益却很小。
- `sha256After` 不用 JCS——快照里有 `costIn/costOut` 浮点，JCS 直接拒绝浮点。改用 `sha256(serde_json::to_vec(&Snapshot))`：字段顺序由结构体定，语义相同则字节相同。
- 每环强制写 `seq = toSeq`，不指望发布端记得在 ops 里写；漏了会得到「内容新、seq 旧」的快照，下一轮从头再来。

**客户端**
- 增量前提三条：`since > 0`、本地 `snapshot.json` 的 seq == since、`plan_chain` 能从 since 连续走到 manifest.seq（≤24 环，环比空转、不许回头）。任一不满足 → `Ok(None)` → 下全量，不算错误。
- 补丁链任何失败（摘要不符 / 断链 / 结构非法）→ **回退全量**，`tracing::warn!` 带 from/to。增量只省流量，不是真相来源。
- `Applied.snapshot` 把这次生效的完整快照带出来，网关写 `snapshot.json` 当下一轮基线。
- 全量补了 64MB 上限：摘要校验在下载**之后**才做，不设上限就没机会了。

**发布端**
- `sign_feed --patch-from <prev.json>` 自动 diff + 写 `patches/{from}-{to}.json` + manifest 带 patches。
- `diff()` 带**自检**：生成完先自己套一遍，套不上就退回整体 replace。宁可下一个全量补丁，也不能让客户端拿到拼错的目录——那种错误不报错，只让模型列表悄悄少几条。
- 数组按 `id` 匹配做增量（providers/models 都有 id）；先递归共有元素（用原始下标）→ 倒序删除 → 末尾追加。顺序变化 diff 表达不了，自检会退化成整体 replace。

**真机验证**（39KB 快照，改 3 处）
- 补丁 **445 字节 vs 全量 32839 字节**（1.4%），5 个 op 精准对应改动。
- 本地起 http.server：第一次全量 → seq 1；随后**删掉 snap2.json**（404）只留 patch，第二次仍更新到 seq 2，基线快照核对：m0-new 在、m0-3 的 context 变 200000、m1-0 被移除。
- e2e 固化这三个场景（`feed_e2e` 场景 4/5/6）：只有补丁也能更新、坏补丁不推进版本、无基线回退全量。
- 新增 `examples/feed_sync.rs`：手动同步并打印 seq/错误/安全阀/事件，排查用。
